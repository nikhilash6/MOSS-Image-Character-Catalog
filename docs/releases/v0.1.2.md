# v0.1.2 — Windows startup fixes / Windows起動修正

## 日本語

- dorakeyさんの [Issue #1](https://github.com/ukr8b3g-cmyk/MOSS-Image-Character-Catalog/issues/1) の報告に対応。タイトル中の `&` を `^&` に修正。
- カタログと比較ツールのWindows bootstrapで `py.exe -0p` の一覧解析を廃止。有効なPATH Pythonを先に採用し、必要な場合は `py -3 -c "import sys; print(sys.executable)"` 等でPython自身に問い合わせます。明示パスの優先、Python 3.10以上の検査、旧版/未導入/パス不正のエラー区分は維持。
- 問い合わせはタイムアウト付きで標準出力と標準エラーを分け、UTF-8を使用。問い合わせ子プロセスではPython自動インストールを抑止し、利用者の環境設定を永続変更しません。
- 画像はv0.1.1と同じ33,937キャラクター＋221スタイル＝34,158枚。未選別、プロンプト、生成設定、作品内カウント順は維持。過去のReleaseは保持。
- 新しいフォルダーに全ZIPを展開してください。個人の画像・編集・判定を含む旧フォルダーへ無条件に上書きしないでください。

### 検証と限界

Windows PowerShell 5.1 / cmd.exe、Miniconda Python 3.13.11、Pillow 12.2.0。起動の16項目が合格。日本語・空白・`&` を含むパス、引数引継ぎ、終了コード、PATH、pyのみ、旧い/不正な既定、明示パス、未導入を確認。pyのみ・旧版などはラベル付きC#テスト実行ファイルで模擬し、実機のPythonやレジストリーは変更していません。

独立した実アプリのコピーでCMDから起動、カタログ・編集画面・info/list APIが200、比較セットアップの `--help`、通常終了後のPID終了とHTTP停止を確認。これはデータなしの起動確認で、全34,158枚の負荷試験や比較判定・実ブラウザー操作のE2E確認ではありません。報告者と同じPython探索失敗は未再現で回答待ちです。タイトルの別コマンド解釈エラーは実機で再現しましたが、その条件では後続処理も継続しており、単独で常に起動不能になるとは断定しません。Python 3.13全般の非互換を示す結果ではありません。macOS/Linuxや過去の全Pythonマトリクスは再検証していません。

## English

- Thanks to dorakey for [Issue #1](https://github.com/ukr8b3g-cmyk/MOSS-Image-Character-Catalog/issues/1). Escape the Windows title's `&` as `^&`.
- Both catalog and comparison bootstraps now check usable PATH Python first, then ask Python for `sys.executable` through `py` rather than parse `py.exe -0p` text. Explicit-interpreter priority, the Python 3.10 minimum and existing error classifications remain.
- Discovery separates stdout/stderr, has a timeout and uses UTF-8. Its child environment suppresses automatic Python installation without changing the user's persistent configuration.
- Same uncurated 33,937 character images + 221 styles = 34,158 images as v0.1.1. Prompts, generation settings, source-count sorting and earlier releases are preserved.
- Extract the entire ZIP into a new folder. Keep any previous folder containing personal images, edits or judgments.

### Validation and limitations

Windows PowerShell 5.1 / cmd.exe, Miniconda Python 3.13.11, Pillow 12.2.0: 16 startup checks passed, including Unicode/space/ampersand paths, arguments, exit status, PATH, py-only discovery, old/invalid defaults, explicit paths and missing Python. Labelled C# fixtures emulate py-only/old cases; no installed Python or registry was changed.

An isolated copy of the real app started through CMD: catalog/editor/info/list HTTP routes returned 200, comparison setup accepted `--help`, and normal shutdown removed the exact test PID and HTTP listener. This empty-data smoke check is not a full-collection performance test or browser/comparison-judgment E2E test. The reporter's exact Python-discovery failure is not yet reproduced; environment details are still requested. The title parsing error reproduced, but processing continued in that condition, so it is not claimed to always prevent startup on its own. This is not evidence of a general Python 3.13 incompatibility. macOS/Linux and the previous full Python matrix were not rerun.
